Implementation capability report

QO-100 WebSDR
Supported modes

Single-SDR wideband reception · Native DVB-S/S2 decoding · Multi-user TS delivery

Prepared 16 November 2026 · Code baseline: d9a33cb
Repository: /root/dvbs-websdr

One SDRone is sufficient. The server captures the full receive window once, extracts each selected channel digitally, and shares a native decoder between users watching the same signal. Browsers receive transport streams and spectrum updates, not IQ.

  • Frame size can be automatic or restricted. Pilots are recognized from signalling; current native test fixtures use pilots enabled.
  • Short-frame FEC 9/10 is rejected by the pinned decoder. The MODCOD table does not imply that every frame/rate combination is valid or tested.
  • Operational target: packetized single-transport-stream reception using stable coding/modulation. ACM/VCM and multistream selection are not qualified features.

Filtering and sensitivity limits

Matched-filter roll-off settings are 0.35, 0.25 and 0.20, selected manually. The reported waveform checks use 0.35; this is also the nominal DVB-S test profile.

DVB-S2 FEC uses hard-decision LDPC bit-flipping plus BCH. This is not a soft-decision LDPC implementation. Clean-waveform success does not establish near-threshold sensitivity, LNB phase-noise tolerance or reliable reception of every high-order APSK mode.

What Auto does

  1. Estimate center frequency and RRC half-power width around the selected signal.
  2. Rank common symbol rates and try up to three nearby candidates. Without a reliable estimate, use the numeric field as a rate hint.
  3. Try DVB-S2 PLS acquisition, then DVB-S QPSK/FEC candidates for each rate, unless the user restricts the standard or parameters.
  4. Confirm only after native lock, transport sync, and CRC-valid PAT and PMT program tables.

Per-candidate acquisition windows are 2.5–12 seconds. Search cycles can repeat while a subscriber remains. There is no guaranteed overall acquisition time. Auto does not exhaustively search all rates, detect roll-off blindly, or decode every visible signal continuously.

For custom rates, weak/overlapping signals or a poor estimate, disable Auto common rates and enter the exact rate. Standard, DVB-S FEC, DVB-S2 MODCOD, frame size and roll-off can be restricted manually.

03 / Receiver, delivery and playback modes

One receiver, multiple users

Operating modeBehavior

Other capture spans1.536, 2.048, 5 and 8 MS/s are available. They do not cover the full WB window. The first viewer defines capture settings.
Independent viewingEach different signal gets a digital mixer, filter, decimator and native decoder. Compatible viewers of the same signal share its decoder.
Waterfall onlyReleases the user's decoder subscription while retaining the shared overview. Last subscriber stops its decoder; last receiver user releases the SDR.

At most one SDR is opened. If several are plugged in, startup selection is supported; a second receiver is neither required nor opened for another channel. Capture center/span/gain are retained while users remain. An external, DC-isolated LNB supply is needed; the SDR bias tee stays off.

Transport and browser playback

The network carries recovered 188-byte MPEG-TS packets, compact FFT updates and status. The server does not transcode video. Tested browser media combinations are MPEG-2/MP2, H.264/AAC and HEVC (H.265)/AAC. The player selects the first video/audio streams; program/track selection is not exposed.

Current display output is 320×240 at 10 fps with mono 48 kHz audio, decoded in roughly three-second batches. This adds latency. TS download retains up to 32 MiB of delivered packets without display rescaling; reception errors can still cause packet loss.

Defaults are four decoder jobs, two acquisition probes and 64 viewers. These are software limits, not a measured 64-user capacity guarantee.

What has been verified

Downloaded TS check1121 packets checked; 1121 source matches, zero bad sync bytes and zero TEI flags. PAT/PMT validation passed.
Physical receiver checksShared receive-only 10 MS/s capture, continued service after one viewer left, second-SDR rejection, and Linux-driver restoration passed. Available SDRs were tested sequentially, not as a required pair.
Lifecycle and boundsIndependent retuning, decoder-capacity rejection, last-user cleanup, slow-client isolation, and shutdown/reaping of native processes passed.
Live QO-100 DVB-S2 reception remains unverified. Recorded-IQ tests establish software operation under controlled conditions. They do not qualify satellite sensitivity, dish alignment, LNB stability, phase noise, adjacent-channel performance, every MODCOD or long-duration operation.

Outside the supported or qualified scope

DVB-S2X and additional constellations; DVB-T/T2 and other broadcast standards; GSE/generic data services; multistream/ISI selection; ACM/VCM adaptation; exhaustive blind symbol-rate detection; soft-decision LDPC; and full-resolution/stereo browser display as currently configured. Not every implemented FEC/frame/pilot combination has a dedicated test.
